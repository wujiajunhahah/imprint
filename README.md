# imprint

**一套克制优先的产品判断规则。** 装进你的 agent，让它默认少做而不是默认多加。

大多数 AI 生成的产品有一组共同倾向：多一个提醒、多一个弹窗、多一个实时数字、多一个动效、多一句"大幅提升"。这套规则的作用是让这些默认动作在发生前停下来。

---

## 它会改变什么

| 场景 | 默认行为 | 装完之后 |
|---|---|---|
| 给"久坐提醒"加功能 | 每 45 分钟弹通知 | 只在环境里做最小提示；专注模式完全不输出；提供个体基线 |
| 写效果宣称 | "专注时长提升 30%" | "单人一周配对观察，操作步数 60→37；样本 1 人，只作方向性证据" |
| 设计状态反馈 | 红色脉冲闪 1.5 秒 | motion 260ms 语义明确 / breath 5s 周期不要求回应 |
| 加一个仪表盘 | 实时数字大屏 | 默认不给数字，只在用户主动回看时呈现 |

一句话：**它让产品想帮忙的方式，变成让用户更少需要它。**

---

## 三条底层立场

1. **有证据才配打断。** 一次误报的代价大于一次漏报。
2. **反馈放进环境，不是又一个屏幕。**
3. **写下"这不能证明什么"**，比多写一个优点更能建立可信度。

核心是**拒绝清单**——印记不在"我加了什么"，在"我拒绝做什么"。

## 装法

**方式一：技能目录**（Claude Code / Cursor / 任何支持 skills 协议的 agent）

```bash
git clone <repo> ~/.agents/skills/imprint
```

**方式二：只拿规格**（任何 agent，无需 skills 支持）

把 `DESIGN.md` 复制进你的项目根目录，然后在你的 `AGENTS.md` 里加一句：

```markdown
构建 UI 前先读 DESIGN.md。frontmatter 里的 token 是规范性的；
偏离 token 的值视为需要说明的例外，不是自由发挥。
```

`DESIGN.md` 自带 frontmatter 规范（动效时长、缓动、介入阈值、排版约束）与散文立场（Direction / Mood / Decisions Log / Refusals）。**它是机器可读的**——token 里有的值不算问题，偏离 token 才算。

## 文件

```
imprint/
├── SKILL.md                    判断规则（规则 / 为什么 / 反例 三段式）
├── DESIGN.md                   可移植的品味规格（token + 立场 + 决定日志）
├── AGENTS.md                   agent 读法（顺序、优先级、什么时候该问）
├── references/
│   ├── refusal-list.md         八条拒绝 + 例外 + 冲突优先级
│   └── cases.md                三个案例：规则怎么改变决定
└── scripts/validate.py         自检：格式、规则三段完整性、**泄露扫描**
```

---

## 关于"反例"这一段

每条规则都是**规则 / 为什么 / 反例**三段。这不是格式洁癖：

- 只有规则 → 会变成教条，接收方机械执行
- 加上为什么 → 接收方能在新情境里推广
- 加上反例 → 接收方知道边界在哪，不会把规则用到不该用的地方

**写不出"为什么"的条目不是规则，是偏好**——那种情况应该回退到"照参照物判断"，而不是伪装成规则。

`scripts/validate.py` 会检查这一点：规则表缺列直接报错。

---

## 自检

```bash
python3 scripts/validate.py
```

检查项：DESIGN.md 格式与必需 token、规则表三段完整性、**身份泄露扫描**（姓名/邮箱/项目名/个人链接）、无网络无遥测、体积上限。

---

## 它不是给谁用的

**不适用于**游戏、营销落地页、以娱乐为主的消费产品——它们的注意力模型与这套规则相反。

**也不适用于**需要实时诊断的场景（医疗监测、运动训练）——那时"实时可见"就是产品价值本身。这些例外写在每条规则的"反例"列里。
