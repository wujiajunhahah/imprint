# imprint

**给你的 AI 装上另一套判断。**

你和 AI 一起做产品时，它有一个默认倾向：多一个提醒、多一个弹窗、多一个实时数字、多一句"大幅提升"。
这堆文件的作用，是让它在动手前先停一下。

---

## 先看一个例子

你说：

> 给我们的专注 App 加一个久坐提醒。

**没装之前，agent 会这么做：**

> 好的，我加一个定时器，每 45 分钟弹一次通知"该起来活动了"，带一个"稍后提醒"按钮。

**装了之后：**

> 先等一下，这个提醒有三个问题：
>
> 1. 45 分钟是**固定阈值**，不看用户状态 —— 有人那 45 分钟正在写代码
> 2. **弹窗本身就是一次打断**，跟"专注 App"的前提冲突
> 3. 如果不提醒，用户会损失什么？**答不上来**
>
> 我的建议：只在**连续静止超过阈值且当前不在通话**时，做一次环境化提示（屏幕边缘的光，或桌面设备一次极轻微的动作）；专注模式完全不输出，只在用户主动回看时显示"今天有 3 段长时间静止"；先记录一周，再给个体基线。
>
> 要按这个做，还是你有别的考虑？

**区别不是"多了一个功能"，而是它先反问了三次。**

## 装法（30 秒）

```bash
git clone https://github.com/wujiajunhahah/imprint.git ~/.agents/skills/imprint
```

然后正常干活。agent 遇到"加提醒 / 加动效 / 写效果宣称"这类决定时，会按这套规则走。

**任何 agent 都能用**（不要求支持 skills 协议）：把 `DESIGN.md` 复制进你的项目根目录，在你的 `AGENTS.md` 里加一句：

```markdown
构建 UI 前先读 DESIGN.md。frontmatter 里的 token 是规范性的。
```

---

## 里面是什么

| 文件 | 一句话 |
|---|---|
| `SKILL.md` | 五组判断规则（什么情况下不出手），每条是「规则 / 为什么 / 反例」 |
| `DESIGN.md` | 可移植规格：动效时长、介入阈值、排版约束（机器可读）+ 立场与决定日志 |
| `references/refusal-list.md` | 八条"不做"，每条带例外 |
| `references/cases.md` | 三个案例，看规则如何改变决定 |
| `scripts/validate.py` | 自检，含泄露扫描 |

---

## 八条"不做"

不做打断式通知 · 不做实时数字焦虑 · 不做通用阈值 · 不做不可中断的自动化 · 不做无证据的效果宣称 · 不做装饰性动效 · 不做"首个/领先"式表述 · 不做让用户误以为是人的 AI 表达

**印记不在"加了什么"，在"拒绝什么"。**

---

## 为什么每条规则都要写"反例"

每条规则都是**规则 / 为什么 / 反例**三段：

- 只有规则 → 变成教条，agent 机械执行
- 加上为什么 → 它能在新情境里推广
- 加上反例 → 它知道边界，不会用到不该用的地方

**写不出"为什么"的条目不是规则，是偏好。** `validate.py` 会拦——规则表缺列直接报错。

---

## 自检

```bash
python3 scripts/validate.py
```

检查：DESIGN.md 格式、规则三段完整性、泄露扫描、脚本无网络无遥测、体积上限。

---

## 不适用

游戏、营销落地页、以娱乐为主的消费产品——它们的注意力模型跟这套规则相反。

需要实时诊断的场景（医疗监测、运动训练）也不适用，那时"实时可见"就是产品价值本身。这些例外写在每条规则的"反例"列里。

---

## 一句话总结

它让产品想帮忙的方式，变成**让用户更少需要它**。
